# EC Product Registration Automation

Python / Playwrightで、ECの商品登録業務を模した画面操作を自動化するポートフォリオです。
検索から商品選別、予約登録、次ページへの移動までを実行し、成功照合と異常時停止を行います。

**対象はローカルの模擬ECツールです。実際のECサービスへの接続・登録実績を示すものではありません。** 商品は架空のサンプルデータです。

## 主な機能

- キーワード検索と一覧の商品情報取得
- NG語、価格、在庫、登録状態による対象選別
- チェックボックスの選択・解除とページ単位の予約登録
- 想定した確認ポップアップだけを承認
- 完了メッセージと商品状態の両方で成功を照合
- ドライラン、重複IDの除外、一覧循環の検知、ページ上限
- STOPファイルによる停止要求、JSONログ、異常時のスクリーンショット

## 構成と設計

```text
automation.py       CLI・画面操作・反復・停止・結果保存
rules.py            商品の判定（画面操作から分離）
mock_server.py      ローカルHTTPサーバー
mock.html           操作対象の模擬画面とサンプル商品
tests/test_lab.py   判定・ブラウザ操作のテスト
requirements.txt   Python依存ライブラリ
```

処理は「検索 → 一覧取得 → 条件判定 → チェック操作 → 予約 → 成功照合 → 次ページ」です。
予約結果を確認できない場合は自動再送せず停止し、未確認IDをログへ残します。
実行時にAI APIは使用せず、APIキー・パスワードは不要です。追加のサービス利用料やAPI従量課金なしでローカル実行できます。

## セットアップ（Windows / PowerShell）

Python 3.10.11、Playwright 1.64.1、Chromiumで動作確認しています。
リポジトリを取得し、そのルートフォルダで実行してください。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PLAYWRIGHT_BROWSERS_PATH="$PWD\.browsers"
.\.venv\Scripts\python.exe -m playwright install chromium
```

別のPowerShellを開いた場合も、リポジトリのルートへ移動して次の環境変数を設定します。
ブラウザの保存先を示す通常設定であり、秘密情報ではありません。

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH="$PWD\.browsers"
```

## 実行

```powershell
# 選別・チェック操作だけ。予約しない
.\.venv\Scripts\python.exe automation.py --headed

# 模擬画面で予約まで実行
.\.venv\Scripts\python.exe automation.py --headed --execute

# キーワードを指定
.\.venv\Scripts\python.exe automation.py --headed --execute --keyword ノート
```

通常データでは9商品中、A001・A005・A007の3商品が対象です。
`--headed`を省略するとブラウザは非表示で動作します。表示する場合も実行終了時に閉じます。
ドライランでもチェック操作とページ送りは行いますが、予約ボタンは押しません。

## 手動で模擬画面を操作

```powershell
.\.venv\Scripts\python.exe mock_server.py
```

[ローカル画面](http://127.0.0.1:8765/)を開きます。
検索後、対象以外のチェックを外して「選択商品を予約登録」→確認でOK→完了表示を確認→「次の一覧」を繰り返します。
各ページでは最初に全選択されているので、予約前に選び直してください。予約後の再描画でも全選択に戻ります。
サーバーはCtrl+Cで終了します。

## 選別条件

|条件|対象とする範囲|
|---|---|
|商品名|「禁止」「ジャンク」を含まない|
|価格|1,000〜10,000円（両端を含む）|
|在庫|1以上|
|状態|未登録|

これらはデモ用の仮条件です。`rules.py`で判定し、対象ならNone、除外なら理由を返します。
複数の除外条件に該当すると、最初に当たった理由を返します。

## ログと停止・復旧

ログは`runs/<実行日時>/result.json`、異常時の画面は同じフォルダの`error.png`へ保存します。

|項目|意味|
|---|---|
|status|success / stopped|
|decisions|各商品の対象・除外理由|
|completed|成功確認できた商品ID|
|pending_verification|送信結果の照合が完了していない商品ID|

プロジェクト直下へ`STOP`というファイルを置くと、次の一覧処理開始時または予約直前に停止します。
送信済みの操作を取り消す機能ではありません。再開前にログと画面状態を確認し、STOPを削除します。
未確認IDがあるときは履歴を照合し、無条件に再送しないでください。
正常終了は終了コード0、処理内の例外は1です。

CLIは毎回新しいブラウザ環境で起動するため、前回や手動ブラウザの予約履歴を引き継ぎません。
手動画面の履歴はそのブラウザのlocalStorageに残り、サイトデータを消すと初期化できます。
実行ログ・画像には実環境で個人情報等が含まれ得るため、このリポジトリの公開対象から除外しています。

## テストと異常シナリオ

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

# 意図的に登録失敗を再現（停止と終了コード1が期待結果）
.\.venv\Scripts\python.exe automation.py --headed --execute --scenario error
```

10テストで、判定境界、不正データ、ドライラン、通常登録と同環境内での再実行、空一覧、検索、重複ID、異常停止、ページ上限、STOPを検証します。
異常停止テストでは登録エラー・未知の確認・一覧循環をサブテストで確認します。
`--scenario`には`empty`、`error`、`loop`、`unknown`、`duplicate`を指定できます。

## 実ツールへの適用範囲

ログイン、二段階認証、予約日時指定、外部通知、常駐運用、実環境の永続的な重複管理は未実装です。
商品情報は教材用のdata属性から取得します。実ツールでは要素の特定、業務条件、確認文、成功判定を作り替える必要があります。
非同期の一覧読込には追加の待機が必要で、登録後に一覧が減るツールではページ送り方式も検討します。
この模擬テストだけで実ECの動作を保証するものではありません。
